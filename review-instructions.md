# Инструкция для проведения AI-ревью кода (Review Instructions)

## 1. Цель (Goal)

Провести строгий аудит качества кода в репозитории `clean-code-todo` на соответствие принципам Clean Code и правилам автоматизации. Твоя задача — найти скрытые проблемы в архитектуре, стилистике, конфигурациях инструментов и чистоте кода.

## 2. Границы (Boundaries)

- **Что проверять:** Файлы конфигураций линтера и форматтера (`eslint.config.js`, `.prettierrc`, `.prettierignore`, `.gitignore`, `package.json`, `.husky/pre-commit`) и финальную логику приложения в `app.js`.
- **Чего не трогать:** Запрещено предлагать изменения в файле автоматического воркфлоу `.github/workflows/check.yml`. Структуру разметки и стилей в `index.html` и `style.css` следует воспринимать как фиксированные ограничения интерфейса, проверяя только их форматирование.
- **Ограничение роли:** Ты выступаешь исключительно в роли аналитика и рецензента. Ты **не должен редактировать файлы** напрямую.

## 3. Критерий готовности (Definition of Done)

Ревью считается полностью завершенным только тогда, когда:

1. Проверены все конфигурационные файлы конвейера сборки.
2. Проанализирована логика и структура функций в итоговом файле `app.js`.
3. Сгенерирован полноценный итоговый отчет в формате markdown строго по структуре ниже.

## 4. Формат вывода (Output Format)

Ты должен записать результаты своего анализа в файл `review-report.md` в корневом каталоге проекта. Отчет должен быть составлен на **русском языке**, а все замечания сгруппированы по категориям задания:

- Мёртвый код
- Дублирование обработчиков и логики
- Имена, которые не читаются без комментариев
- Комментарии, которые пересказывают код
- Функции, которые не читаются целиком

Каждое отдельное замечание внутри категории обязано содержать **четыре обязательные части**:

1.  **Место в коде:** Укажи конкретные строки, имя функции или название файла.
2.  **Проблема:** Понятно назови и опиши нарушение принципов чистого кода.
3.  **Условие, при котором она проявляется:** Опиши контекст, сценарий или проблему поддержки кода, к которой приводит это нарушение.
4.  **Способ проверить исправление:** Напиши пошаговый алгоритм действий (ручной тест в браузере или команду проверки), который докажет, что проблема устранена.
